# 3. Управляющие пакеты MQTT

Раздел описывает каждый управляющий пакет MQTT. Из-за объёма разбит на несколько выпусков:

- **Выпуск 1:** 3.1 CONNECT, 3.2 CONNACK
- **Выпуск 2:** 3.3 PUBLISH, 3.4 PUBACK, 3.5 PUBREC, 3.6 PUBREL, 3.7 PUBCOMP
- **Выпуск 3:** 3.8 SUBSCRIBE, 3.9 SUBACK, 3.10 UNSUBSCRIBE, 3.11 UNSUBACK
- **Выпуск 4 (в этом файле, завершающий):** 3.12 PINGREQ, 3.13 PINGRESP, 3.14 DISCONNECT, 3.15 AUTH

---

## 3.1. CONNECT — запрос на подключение

Пакет CONNECT отправляется клиентом серверу **первым** после установки сетевого соединения. Он может быть отправлен только один раз за время жизни соединения. Повторная отправка CONNECT — нарушение протокола, и сервер **ДОЛЖЕН** закрыть соединение.

### 3.1.1. Фиксированный заголовок

| Поле | Значение |
|------|----------|
| Тип пакета | 1 (0b0001) |
| Флаги | 0 0 0 0 (зарезервировано) |
| Remaining Length | длина переменного заголовка + длина полезной нагрузки |

### 3.1.2. Переменный заголовок

Переменный заголовок CONNECT состоит из следующих полей в строгом порядке:

1. **Protocol Name** (UTF-8 String)
2. **Protocol Level** (Byte)
3. **Connect Flags** (Byte)
4. **Keep Alive** (Two Byte Integer)
5. **Properties** (Properties)

#### 3.1.2.1. Protocol Name

Строка UTF-8. Для MQTT 5.0 значение — `"MQTT"` (4 байта: `0x00 0x04 'M' 'Q' 'T' 'T'`). Сервер **ДОЛЖЕН** закрыть соединение, если Protocol Name отличается от поддерживаемого.

#### 3.1.2.2. Protocol Level

Byte, указывающий уровень протокола:

| Значение | Версия |
|----------|--------|
| 3 | MQTT 3.1 |
| 4 | MQTT 3.1.1 |
| 5 | MQTT 5.0 |

Для этой спецификации значение = **5**.

#### 3.1.2.3. Connect Flags

Байт, в котором каждый бит управляет отдельной опцией подключения:

```
бит    7        6        5       4    3    2       1        0
     ┌────────┬────────┬───────┬────┬────┬───────┬────────┬────────┐
     │UserName│Password│Will  │Will│Will│ Clean │Reserved│        │
     │        │        │Retain│QoS │Flag│ Start │        │        │
     └────────┴────────┴───────┴────┴────┴───────┴────────┴────────┘
```

- **Бит 0 (Reserved):** зарезервирован, **ДОЛЖЕН** быть 0. Иначе сервер закрывает соединение.
- **Бит 1 (Clean Start):** если 1 — клиент начинает новую сессию; если 0 — пытается возобновить существующую.
- **Бит 2 (Will Flag):** если 1 — в полезной нагрузке присутствуют Will Properties, Will Topic и Will Payload.
- **Биты 3–4 (Will QoS):** уровень QoS для Will-сообщения (0, 1 или 2). Если Will Flag = 0, **ДОЛЖНЫ** быть 0.
- **Бит 5 (Will Retain):** если 1 — Will-сообщение сохраняется как retained. Если Will Flag = 0, **ДОЛЖЕН** быть 0.
- **Бит 6 (Password Flag):** если 1 — в полезной нагрузке есть Password.
- **Бит 7 (User Name Flag):** если 1 — в полезной нагрузке есть User Name.

Ограничения:
- Если Will Flag = 0, то Will QoS **ДОЛЖЕН** быть 0, а Will Retain **ДОЛЖЕН** быть 0.
- Если Will Flag = 1, Will QoS **НЕ ДОЛЖЕН** быть 3.

#### 3.1.2.4. Keep Alive

Two Byte Integer (0–65535 секунд). Задаёт максимальный интервал между передаваемыми клиентом управляющими пакетами.

Правила:
- Если в течение Keep Alive клиент не отправляет никаких пакетов, он **ДОЛЖЕН** отправить PINGREQ.
- Сервер, не получивший пакетов в течение 1.5 × Keep Alive, **ДОЛЖЕН** закрыть соединение как при аномальном отключении.
- Значение 0 отключает механизм Keep Alive.
- Сервер может навязать своё значение через свойство **Server Keep Alive** в CONNACK.

#### 3.1.2.5. Properties

Свойства CONNECT:

| Свойство | Обязательное | Описание |
|----------|:-----------:|----------|
| Session Expiry Interval | нет | Время жизни сессии в секундах после отключения. 0 = сессия заканчивается сразу. Максимум (0xFFFFFFFF) = бессрочно |
| Receive Maximum | нет | Максимум одновременных QoS 1/2 публикаций, которые клиент готов обработать. По умолчанию 65535. 0 запрещён |
| Maximum Packet Size | нет | Максимальный размер пакета, который клиент готов принять. 0 запрещён |
| Topic Alias Maximum | нет | Максимальный Topic Alias, который клиент готов принять. По умолчанию 0 (псевдонимы не поддерживаются) |
| Request Response Information | нет | 0 или 1. Если 1 — клиент просит сервер вернуть Response Information в CONNACK |
| Request Problem Information | нет | 0 или 1. Если 0 — сервер **НЕ ДОЛЖЕН** отправлять Reason String и User Property в пакетах, кроме PUBLISH, CONNACK, DISCONNECT |
| User Property | нет | Пользовательские пары ключ-значение. Может встречаться многократно |
| Authentication Method | нет | Имя метода расширенной аутентификации |
| Authentication Data | нет | Двоичные данные аутентификации. Требует наличия Authentication Method |

### 3.1.3. Полезная нагрузка

Поля полезной нагрузки идут строго в указанном порядке. Наличие каждого поля определяется флагами в Connect Flags:

1. **Client Identifier** (всегда) — UTF-8 строка, уникальный идентификатор клиента.
2. **Will Properties** (если Will Flag = 1) — свойства Will-сообщения.
3. **Will Topic** (если Will Flag = 1) — топик Will-сообщения.
4. **Will Payload** (если Will Flag = 1) — двоичные данные Will-сообщения.
5. **User Name** (если User Name Flag = 1) — UTF-8 строка.
6. **Password** (если Password Flag = 1) — двоичные данные.

#### 3.1.3.1. Client Identifier

UTF-8 строка, идентифицирующая клиента. Сервер использует её для связывания с сессией.

Правила:
- Если Clean Start = 1 и Client Identifier пуст, сервер **ДОЛЖЕН** сгенерировать уникальный идентификатор и вернуть его в CONNACK через свойство Assigned Client Identifier.
- Если Clean Start = 0 и Client Identifier пуст, сервер **ДОЛЖЕН** вернуть CONNACK с Reason Code 0x85 (Client Identifier not valid).
- Сервер **МОЖЕТ** ограничивать допустимые символы и длину; при нарушении возвращает 0x85.

#### 3.1.3.2. Will Properties

Свойства, связанные с Will-сообщением:

| Свойство | Описание |
|----------|----------|
| Will Delay Interval | Задержка публикации Will после отключения. По умолчанию 0 |
| Payload Format Indicator | 0 = неопределённые байты, 1 = UTF-8 |
| Message Expiry Interval | Время жизни Will-сообщения |
| Content Type | Описание типа содержимого (MIME-подобное) |
| Response Topic | Топик для ответа |
| Correlation Data | Данные корреляции |
| User Property | Пользовательские свойства |

#### 3.1.3.3. Will Topic

UTF-8 строка — топик, в который будет опубликовано Will-сообщение. **НЕ ДОЛЖНА** содержать подстановочных знаков `+` или `#`.

#### 3.1.3.4. Will Payload

Двоичные данные — само Will-сообщение.

#### 3.1.3.5. User Name

UTF-8 строка — имя пользователя для аутентификации.

#### 3.1.3.6. Password

Двоичные данные — пароль. Может быть бинарным, не обязательно UTF-8.

### 3.1.4. Действия сервера при получении CONNECT

1. Проверить корректность Protocol Name и Protocol Level. Если не поддерживается — закрыть соединение (или ответить CONNACK с кодом 0x84).
2. Проверить Connect Flags. При нарушении — закрыть соединение.
3. Аутентифицировать клиента, если требуется.
4. Проверить Client Identifier.
5. Определить, продолжается ли существующая сессия.
6. Ответить CONNACK.

## 3.2. CONNACK — подтверждение подключения

CONNACK отправляется сервером клиенту в ответ на CONNECT. Первый пакет, отправляемый сервером.

### 3.2.1. Фиксированный заголовок

| Поле | Значение |
|------|----------|
| Тип пакета | 2 (0b0010) |
| Флаги | 0 0 0 0 (зарезервировано) |
| Remaining Length | 2 + размер Properties |

### 3.2.2. Переменный заголовок

Состоит из:

1. **Connect Acknowledge Flags** (Byte)
2. **Connect Reason Code** (Byte)
3. **Properties** (Properties)

#### 3.2.2.1. Connect Acknowledge Flags

```
бит    7   6   5   4   3   2   1       0
     ┌───┬───┬───┬───┬───┬───┬───────┬──────────┐
     │ 0 │ 0 │ 0 │ 0 │ 0 │ 0 │ 0     │ Session  │
     │   │   │   │   │   │   │       │ Present  │
     └───┴───┴───┴───┴───┴───┴───────┴──────────┘
```

- **Биты 1–7:** зарезервированы, **ДОЛЖНЫ** быть 0.
- **Бит 0 (Session Present):** 1 — сервер возобновил существующую сессию, 0 — началась новая сессия.

Правило: если Connect Reason Code ≠ 0x00 (Success), Session Present **ДОЛЖЕН** быть 0.

#### 3.2.2.2. Connect Reason Code

| Код | Название | Описание |
|-----|----------|----------|
| 0x00 | Success | Успешно |
| 0x80 | Unspecified error | Неопределённая ошибка |
| 0x81 | Malformed Packet | Некорректный пакет |
| 0x82 | Protocol Error | Нарушение протокола |
| 0x83 | Implementation specific error | Ошибка реализации |
| 0x84 | Unsupported Protocol Version | Неподдерживаемая версия протокола |
| 0x85 | Client Identifier not valid | Неверный Client Identifier |
| 0x86 | Bad User Name or Password | Неверные логин/пароль |
| 0x87 | Not authorized | Не авторизован |
| 0x88 | Server unavailable | Сервер недоступен |
| 0x89 | Server busy | Сервер занят |
| 0x8A | Banned | Забанен |
| 0x8C | Bad authentication method | Неверный метод аутентификации |
| 0x90 | Topic Name invalid | Неверное имя топика |
| 0x95 | Packet too large | Пакет слишком большой |
| 0x97 | Quota exceeded | Превышена квота |
| 0x99 | Payload format invalid | Неверный формат полезной нагрузки |
| 0x9A | Retain not supported | Retain не поддерживается |
| 0x9B | QoS not supported | QoS не поддерживается |
| 0x9C | Use another server | Используйте другой сервер |
| 0x9D | Server moved | Сервер перемещён |
| 0x9F | Connection rate exceeded | Превышена частота подключений |

#### 3.2.2.3. Properties

Свойства CONNACK:

| Свойство | Описание |
|----------|----------|
| Session Expiry Interval | Если задано, переопределяет значение из CONNECT |
| Receive Maximum | Максимум одновременных QoS 1/2, которые готов принять сервер |
| Maximum QoS | Максимально поддерживаемый QoS (0 или 1). Если свойство отсутствует — поддерживаются оба |
| Retain Available | 1 = retain поддерживается, 0 = нет |
| Maximum Packet Size | Максимальный размер пакета, который принимает сервер |
| Assigned Client Identifier | Идентификатор, назначенный сервером, если клиент передал пустой |
| Topic Alias Maximum | Максимум Topic Alias, принимаемый сервером |
| Reason String | Строка с описанием причины (для отладки) |
| User Property | Пользовательские пары ключ-значение |
| Wildcard Subscription Available | 1 = подстановочные знаки поддерживаются, 0 = нет |
| Subscription Identifier Available | 1 = Subscription Identifier поддерживается |
| Shared Subscription Available | 1 = общие подписки поддерживаются |
| Server Keep Alive | Если задано, переопределяет Keep Alive из CONNECT |
| Response Information | База для построения Response Topic |
| Server Reference | Адрес другого сервера для использования |
| Authentication Method | Метод расширенной аутентификации |
| Authentication Data | Данные аутентификации |

### 3.2.3. Полезная нагрузка

CONNACK **НЕ ИМЕЕТ** полезной нагрузки.

### 3.2.4. Действия клиента

1. Если Reason Code ≠ 0x00 — закрыть соединение.
2. Если Session Present = 1 — использовать существующую сессию.
3. Учесть свойства: Max QoS, Max Packet Size, Topic Alias Maximum, Server Keep Alive и т.д.

## 3.3. PUBLISH — публикация сообщения

PUBLISH используется как клиентом, так и сервером для передачи сообщения приложения по указанному топику.

### 3.3.1. Фиксированный заголовок

| Поле | Значение |
|------|----------|
| Тип пакета | 3 (0b0011) |
| Флаги | DUP (бит 3), QoS (биты 2-1), RETAIN (бит 0) |
| Remaining Length | длина переменного заголовка + полезной нагрузки |

Флаги:

- **DUP (бит 3):** если 1 — пакет является повторной передачей. Для QoS 0 **ДОЛЖЕН** быть 0.
- **QoS (биты 2-1):** уровень качества обслуживания. Значение 3 запрещено, иначе закрытие соединения.
- **RETAIN (бит 0):** если 1 — сообщение сохраняется на сервере как последнее известное для данного топика.

Правила для RETAIN при доставке подписчику:
- Если подписка создана после публикации retained-сообщения, сервер **ДОЛЖЕН** отправить его с RETAIN = 1.
- Если сообщение доставляется в рамках уже действующей подписки, RETAIN **ДОЛЖЕН** быть 0.
- Если RETAIN = 1 и полезная нагрузка пустая — сервер удаляет retained-сообщение для топика, но всё равно рассылает его текущим подписчикам.

### 3.3.2. Переменный заголовок

1. **Topic Name** (UTF-8 String)
2. **Packet Identifier** (Two Byte Integer) — только для QoS > 0
3. **Properties** (Properties)

#### 3.3.2.1. Topic Name

UTF-8 строка. **НЕ ДОЛЖНА** содержать подстановочных знаков `+` или `#`. Может быть пустой, если используется Topic Alias.

#### 3.3.2.2. Packet Identifier

Присутствует только при QoS 1 и QoS 2. Уникальный идентификатор пакета в рамках текущей сессии (1–65535). Для QoS 0 — отсутствует.

#### 3.3.2.3. Properties

| Свойство | Описание |
|----------|----------|
| Payload Format Indicator | 0 = байты, 1 = UTF-8 |
| Message Expiry Interval | Срок жизни сообщения в секундах |
| Topic Alias | Числовой псевдоним топика |
| Response Topic | Топик для ответа (request/response) |
| Correlation Data | Данные корреляции |
| User Property | Пользовательские пары ключ-значение |
| Subscription Identifier | Идентификатор подписки (только от сервера к клиенту) |
| Content Type | MIME-подобное описание содержимого |

### 3.3.3. Полезная нагрузка

Полезная нагрузка — это само сообщение приложения. Может быть пустой (нулевой длины).

### 3.3.4. Действия получателя

Клиент, получивший PUBLISH, **ДОЛЖЕН**:
1. Проверить корректность пакета.
2. Для QoS 1 отправить PUBACK.
3. Для QoS 2 отправить PUBREC.
4. Доставить сообщение приложению.

## 3.4. PUBACK — подтверждение публикации (QoS 1)

PUBACK отправляется получателем PUBLISH с QoS 1.

### 3.4.1. Фиксированный заголовок

| Поле | Значение |
|------|----------|
| Тип пакета | 4 (0b0100) |
| Флаги | 0 0 0 0 |
| Remaining Length | 2 (или 3+ при наличии Reason Code/Properties) |

### 3.4.2. Переменный заголовок

1. **Packet Identifier** (Two Byte Integer).
2. **PUBACK Reason Code** (Byte) — опционально. Если отсутствует — 0x00 (Success).
3. **Properties** (Properties) — опционально.

#### 3.4.2.1. PUBACK Reason Code

| Код | Название |
|-----|----------|
| 0x00 | Success |
| 0x10 | No matching subscribers |
| 0x80 | Unspecified error |
| 0x83 | Implementation specific error |
| 0x87 | Not authorized |
| 0x90 | Topic Name invalid |
| 0x91 | Packet Identifier in use |
| 0x97 | Quota exceeded |
| 0x99 | Payload format invalid |

### 3.4.3. Полезная нагрузка

Нет.

## 3.5. PUBREC — получение публикации (QoS 2, шаг 1)

PUBREC — ответ получателя на PUBLISH с QoS 2.

| Поле | Значение |
|------|----------|
| Тип пакета | 5 (0b0101) |
| Флаги | 0 0 0 0 |
| Remaining Length | 2 (или 3+ с Reason Code/Properties) |

### 3.5.2. Переменный заголовок

1. **Packet Identifier**
2. **PUBREC Reason Code** (опционально)
3. **Properties** (опционально)

| Код | Название |
|-----|----------|
| 0x00 | Success |
| 0x10 | No matching subscribers |
| 0x80 | Unspecified error |
| 0x83 | Implementation specific error |
| 0x87 | Not authorized |
| 0x90 | Topic Name invalid |
| 0x91 | Packet Identifier in use |
| 0x97 | Quota exceeded |
| 0x99 | Payload format invalid |

Если код ≥ 0x80 — отправитель **ДОЛЖЕН** прекратить процедуру (не отправлять PUBREL).

### 3.5.3. Полезная нагрузка

Нет.

## 3.6. PUBREL — освобождение публикации (QoS 2, шаг 2)

PUBREL — ответ отправителя PUBLISH после получения PUBREC.

### 3.6.1. Фиксированный заголовок

| Поле | Значение |
|------|----------|
| Тип пакета | 6 (0b0110) |
| Флаги | 0 0 1 0 (обязательно) |
| Remaining Length | 2 (или 3+ с Reason Code/Properties) |

Флаги **ДОЛЖНЫ** быть `0010`. Иначе получатель закрывает соединение.

### 3.6.2. Переменный заголовок

1. **Packet Identifier**
2. **PUBREL Reason Code** (опционально)
3. **Properties** (опционально)

| Код | Название |
|-----|----------|
| 0x00 | Success |
| 0x92 | Packet Identifier not found |

### 3.6.3. Полезная нагрузка

Нет.

## 3.8. SUBSCRIBE — подписка

SUBSCRIBE отправляется клиентом серверу для создания одной или нескольких подписок.

### 3.8.1. Фиксированный заголовок

| Поле | Значение |
|------|----------|
| Тип пакета | 8 (0b1000) |
| Флаги | 0 0 1 0 (обязательно) |
| Remaining Length | длина переменного заголовка + полезной нагрузки |

Флаги **ДОЛЖНЫ** быть `0010`.

### 3.8.2. Переменный заголовок

1. **Packet Identifier** (Two Byte Integer).
2. **Properties** (Properties).

| Свойство | Описание |
|----------|----------|
| Subscription Identifier | Числовой идентификатор подписки (1 – 268 435 455) |
| User Property | Пользовательские пары ключ-значение |

### 3.8.3. Полезная нагрузка

Список записей «фильтр + параметры»:

1. **Topic Filter** (UTF-8 String)
2. **Subscription Options** (Byte)

#### 3.8.3.1. Topic Filter

UTF-8 строка, может содержать `+` и `#`. Минимум 1 символ, максимум 65535 байт.

#### 3.8.3.2. Subscription Options

```
бит    7   6        5        4   3   2       1       0
     ┌───┬────────┬────────┬───┬───┬───────┬───────┬────────┐
     │ 0 │  NL    │  RAP   │ 0 │ 0 │  QoS  │  QoS  │   QoS  │
     └───┴────────┴────────┴───┴───┴───────┴───────┴────────┘
```

- **Биты 0–1 (QoS):** максимальный QoS подписки (0, 1 или 2). Значение 3 — нарушение.
- **Биты 2–3:** зарезервированы, **ДОЛЖНЫ** быть 0.
- **Бит 4 (RAP, Retain As Published):** если 1 — сохранять флаг RETAIN из оригинала; если 0 — обнулять.
- **Бит 5 (NL, No Local):** если 1 — не доставлять клиенту его же публикации. Несовместим с общими подписками.
- **Биты 6–7:** зарезервированы, **ДОЛЖНЫ** быть 0.

### 3.8.4. Действия сервера

1. Проверяет Packet Identifier.
2. Проверяет синтаксис фильтров.
3. Проверяет права (авторизация).
4. Проверяет Subscription Options.
5. Добавляет/обновляет подписки.
6. Отправляет SUBACK.
7. Рассылает retained-сообщения.

Повторная подписка на тот же фильтр **полностью заменяет** старую.

## 3.14. DISCONNECT — отключение

DISCONNECT отправляется клиентом **или** сервером для корректного закрытия соединения. В отличие от простого разрыва, отправка DISCONNECT указывает, что Will-сообщение **НЕ ДОЛЖНО** публиковаться.

### 3.14.1. Фиксированный заголовок

| Поле | Значение |
|------|----------|
| Тип пакета | 14 (0b1110) |
| Флаги | 0 0 0 0 |
| Remaining Length | 0 (или больше при наличии Reason Code/Properties) |

### 3.14.2. Переменный заголовок

Если Remaining Length = 0, Reason Code считается 0x00 (Normal disconnection), а Properties отсутствуют. Иначе:

1. **DISCONNECT Reason Code** (Byte)
2. **Properties** (Properties) — опционально

#### 3.14.2.1. DISCONNECT Reason Code

| Код | Название |
|-----|----------|
| 0x00 | Normal disconnection |
| 0x04 | Disconnect with Will Message |
| 0x80 | Unspecified error |
| 0x81 | Malformed Packet |
| 0x82 | Protocol Error |
| 0x83 | Implementation specific error |
| 0x87 | Not authorized |
| 0x89 | Server busy |
| 0x8B | Server shutting down |
| 0x8D | Keep Alive timeout |
| 0x8E | Session taken over |
| 0x8F | Topic Filter invalid |
| 0x90 | Topic Name invalid |
| 0x93 | Receive Maximum exceeded |
| 0x94 | Topic Alias invalid |
| 0x95 | Packet too large |
| 0x96 | Message rate too high |
| 0x97 | Quota exceeded |
| 0x98 | Administrative action |
| 0x99 | Payload format invalid |
| 0x9A | Retain not supported |
| 0x9B | QoS not supported |
| 0x9C | Use another server |
| 0x9D | Server moved |
| 0x9E | Shared Subscriptions not supported |
| 0x9F | Connection rate exceeded |
| 0xA0 | Maximum connect time |
| 0xA1 | Subscription Identifiers not supported |
| 0xA2 | Wildcard Subscriptions not supported |

#### 3.14.2.2. Properties

| Свойство | Описание |
|----------|----------|
| Session Expiry Interval | Переопределяет значение из CONNECT (только от клиента) |
| Reason String | Строка с описанием причины |
| User Property | Пользовательские пары |
| Server Reference | Адрес другого сервера (только от сервера) |

### 3.14.3. Полезная нагрузка

Нет.

### 3.14.4. Особые случаи

- Если Reason Code = 0x04 (Disconnect with Will Message) — сервер **ДОЛЖЕН** опубликовать Will-сообщение, как при аномальном отключении.
- Если Reason Code = 0x00 — Will-сообщение **НЕ** публикуется.
- Свойство Session Expiry Interval в DISCONNECT **НЕ ДОЛЖНО** менять значение с «ненулевого» на «ненулевое большее» (можно только уменьшить или установить 0).

## 3.15. AUTH — аутентификация

AUTH (новая в MQTT 5.0) используется для расширенной аутентификации. Обмен AUTH может происходить:

1. Во время подключения (после CONNECT, но до CONNACK).
2. После успешного подключения (для переаутентификации).

### 3.15.1. Фиксированный заголовок

| Поле | Значение |
|------|----------|
| Тип пакета | 15 (0b1111) |
| Флаги | 0 0 0 0 |
| Remaining Length | 0 (или больше) |

### 3.15.2. Переменный заголовок

1. **Authenticate Reason Code** (Byte) — если Remaining Length > 0.
2. **Properties** (Properties) — опционально.

#### 3.15.2.1. Authenticate Reason Code

| Код | Название |
|-----|----------|
| 0x00 | Success |
| 0x18 | Continue authentication |
| 0x19 | Re-authenticate |

#### 3.15.2.2. Properties

| Свойство | Описание |
|----------|----------|
| Authentication Method | Имя метода (обязательно при продолжении процедуры) |
| Authentication Data | Двоичные данные для метода |
| Reason String | Строка с описанием причины |
| User Property | Пользовательские пары |

### 3.15.3. Полезная нагрузка

Нет.

### 3.15.4. Правила использования

- AUTH **МОЖЕТ** отправляться только если в CONNECT/CONNACK был указан Authentication Method.
- При переаутентификации после установки соединения обмен **ДОЛЖЕН** завершиться кодом 0x00 (Success) или ошибкой (≥ 0x80).
- Если код ошибки — сервер закрывает соединение.
