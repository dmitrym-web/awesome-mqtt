# Приложение B. Обязательные нормативные утверждения

Это приложение собирает в одном месте все утверждения вида «X **ДОЛЖЕН** делать Y», разбросанные по спецификации. Оно не добавляет новых требований, а только структурирует существующие.

## B.1. Общие требования

- Все реализации **ДОЛЖНЫ** соблюдать нормативные утверждения, обозначенные **ДОЛЖЕН**, **НЕ ДОЛЖЕН**.
- Зарезервированные биты **ДОЛЖНЫ** быть установлены в 0 и игнорироваться при приёме.
- При нарушении формата пакета получатель **ДОЛЖЕН** закрыть соединение.
- Строки UTF-8 **НЕ ДОЛЖНЫ** содержать U+0000 и суррогатных пар U+D800–U+DFFF.
- Remaining Length **ДОЛЖНА** быть закодирована не более чем 4 байтами.
- При неизвестном свойстве получатель **ДОЛЖЕН** закрыть соединение.

## B.2. CONNECT и CONNACK

- Клиент **ДОЛЖЕН** отправлять CONNECT первым пакетом.
- Клиент **НЕ ДОЛЖЕН** отправлять второй CONNECT в одном соединении.
- Клиент **ДОЛЖЕН** указывать корректный Protocol Name (`MQTT`) и Protocol Level (5 для 5.0).
- Если Clean Start = 0 и Client Identifier пуст — сервер **ДОЛЖЕН** ответить CONNACK 0x85.
- Если Clean Start = 1 и Client Identifier пуст — сервер **ДОЛЖЕН** сгенерировать идентификатор.
- Сервер **ДОЛЖЕН** отвечать CONNACK на каждый CONNECT.
- При Connect Reason Code ≠ 0x00 Session Present **ДОЛЖЕН** быть 0.
- Will QoS **НЕ ДОЛЖЕН** быть 3.
- Password Flag и User Name Flag **ДОЛЖНЫ** быть согласованы с наличием полей в payload.

## B.3. Keep Alive и PING

- Клиент **ДОЛЖЕН** отправлять пакеты в течение интервала Keep Alive.
- При отсутствии других пакетов клиент **ДОЛЖЕН** отправить PINGREQ.
- Сервер **ДОЛЖЕН** разорвать соединение после 1.5 × Keep Alive без активности.
- Сервер **ДОЛЖЕН** отвечать PINGRESP на PINGREQ.

## B.4. PUBLISH и подтверждения

- Для QoS 0 DUP **ДОЛЖЕН** быть 0.
- QoS **НЕ ДОЛЖЕН** быть 3.
- Packet Identifier **ДОЛЖЕН** быть уникален в пределах сессии.
- Topic Name в PUBLISH **НЕ ДОЛЖНО** содержать `+`, `#`.
- Получатель QoS 1 **ДОЛЖЕН** отправить PUBACK.
- Получатель QoS 2 **ДОЛЖЕН** отправить PUBREC и, при PUBREL, PUBCOMP.
- При повторной передаче отправитель **ДОЛЖЕН** установить DUP = 1 (для PUBLISH).
- Получатель **НЕ ДОЛЖЕН** доставлять приложению повторное QoS 1/2 сообщение с тем же id.
- При PUBREC/PUBACK с кодом ≥ 0x80 отправитель **ДОЛЖЕН** прекратить процедуру.

## B.5. SUBSCRIBE и SUBACK

- SUBSCRIBE **ДОЛЖЕН** содержать минимум один фильтр.
- Флаги SUBSCRIBE **ДОЛЖНЫ** быть `0010`.
- QoS в Subscription Options **НЕ ДОЛЖЕН** быть 3.
- NL **НЕ ДОЛЖЕН** использоваться с общими подписками.
- Сервер **ДОЛЖЕН** отвечать SUBACK с кодом для каждого фильтра.
- При неверном синтаксисе фильтра сервер **ДОЛЖЕН** вернуть SUBACK с 0x8F.

## B.6. UNSUBSCRIBE и UNSUBACK

- Флаги UNSUBSCRIBE **ДОЛЖНЫ** быть `0010`.
- Дубликаты фильтров в UNSUBSCRIBE **НЕ ДОПУСКАЮТСЯ**.
- Сервер **ДОЛЖЕН** отвечать UNSUBACK с кодом для каждого фильтра.
- При отсутствии подписки — код 0x11.

## B.7. DISCONNECT и AUTH

- DISCONNECT **ДОЛЖЕН** закрывать сессию при Session Expiry = 0.
- При Reason Code 0x04 Will **ДОЛЖНО** быть опубликовано.
- При Reason Code 0x00 Will **НЕ** публикуется.
- Session Expiry **НЕ ДОЛЖЕН** увеличиваться через DISCONNECT.
- AUTH **ДОЛЖЕН** использовать тот же Authentication Method, что в CONNECT.
- AUTH **НЕ ДОЛЖЕН** использоваться без предварительного согласования метода.

## B.8. Сессия и Will

- Клиент и сервер **ДОЛЖНЫ** хранить состояние QoS 1/2 в течение сессии.
- Сервер **ДОЛЖЕН** хранить подписки и ожидающие сообщения для persistent session.
- При истечении Session Expiry сервер **ДОЛЖЕН** удалить сессию.
- При нормальном DISCONNECT Will **НЕ** публикуется (кроме 0x04).
- При аномальном разрыве Will **ДОЛЖНО** быть опубликовано.
- При подключении с тем же Client Identifier сервер **ДОЛЖЕН** закрыть старое соединение.

## B.9. Retain и Wildcards

- Retained-сообщение **ДОЛЖНО** быть отправлено новой подписке с RETAIN = 1.
- При обычной доставке RETAIN **ДОЛЖЕН** быть 0 (кроме RAP = 1).
- Retained-сообщение **ДОЛЖНО** заменяться новым при той же теме.
- Пустая нагрузка с RETAIN = 1 **ДОЛЖНА** удалять retained.
- `#` **ДОЛЖЕН** быть последним символом в фильтре.
- Фильтры `#` и `+` **НЕ ДОЛЖНЫ** совпадать с топиками, начинающимися с `$`.

## B.10. Свойства и Reason Codes

- Все свойства **ДОЛЖНЫ** встречаться один раз (кроме User Property и Subscription Identifier).
- Property Length **ДОЛЖНА** совпадать с суммой длин свойств.
- Reason Code ≥ 0x80 означает ошибку.
- При Request Problem Information = 0 сервер **НЕ ДОЛЖЕН** включать Reason String в большинство пакетов.
- Topic Alias **НЕ ДОЛЖЕН** превышать Topic Alias Maximum.
- Первый PUBLISH с новым псевдонимом **ДОЛЖЕН** содержать и Topic Name, и Topic Alias.

## B.11. WebSocket transport

- WebSocket **ДОЛЖЕН** работать поверх TCP.
- Фреймы **ДОЛЖНЫ** быть бинарными.
- Подпротокол **ДОЛЖЕН** быть `mqtt`.
- Клиент **ДОЛЖЕН** маскировать фреймы, сервер — **НЕ ДОЛЖЕН**.
- Границы фреймов и пакетов **НЕ** обязаны совпадать.
- MQTT-сессия **ДОЛЖНА** завершаться через DISCONNECT перед закрытием WebSocket.

## B.12. Соответствие

- Реализация **ДОЛЖНА** соблюдать все применимые **ДОЛЖЕН**-требования.
- Неподдерживаемые опциональные функции **ДОЛЖНЫ** объявляться через CONNACK.
- При использовании неподдерживаемой функции сервер **ДОЛЖЕН** вернуть соответствующий Reason Code.
